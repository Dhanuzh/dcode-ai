# Code Mode 2 — scripts that ask, show their work and run in parallel (2026-11-21)

Code Mode (`run_script`, Boa) shipped in v1.0.61. Claude Code 2.1.329 made
Code Mode a first-class feature; its changelog shows what ours lacks. This
plan closes those gaps.

**Status:** built for v1.0.89.

## Gaps (ours vs Claude's)

| Claude Code Mode | dcode-ai before |
|---|---|
| A call that needs approval prompts mid-script; the wait doesn't count against the time limit | call fails: "call it directly" |
| Each tool call the script makes is visible (events, transcript); finished edits stay visible after Esc | inner calls invisible; only the script's result |
| 10-minute limit | 60 s, 50 calls |
| `log`, `preview`, `sleep` built-ins (a script may declare its own) | `print`, `console.log` |
| Runaway loops stopped | loop-iteration limit (kept) |
| Call with no argument works | already (`args ?? {}`) |

## What

1. **Approvals inside a script.** A call whose tier is `Ask` goes through
   the normal path: auto-mode model check, `ApprovalRequested` → the
   user's verdict → `ApprovalResolved`, "always allow" patterns, partial
   hunk approval (`ApprovedModified`). Denied → the call throws in the
   script. Headless `fail_on_ask` → throws with the headless hint.
   Time spent waiting for the user is added back to the script's deadline.
2. **Visible inner calls.** Each call emits `ToolCallStarted` /
   `ToolCallCompleted` with id `<script id>.<n>`, so the transcript, event
   log, `--json` stream and web page show them, and edits that finished
   before Esc are shown as done. Output in events is capped like any tool.
3. **Limits.** 10 minutes, 200 tool calls, 20k characters out. A tool call
   is bounded by what's left of the deadline.
4. **Built-ins.** `log(...)` (= `print`), `preview(value, n = 2000)` (one
   value, JSON for objects, cut at `n` characters), `sleep(ms)` (at most
   what's left of the deadline). Defined in the prelude; a script's own
   `const log = …` shadows them (the body runs in a function scope).
5. **`parallel([...])`.** `parallel([{tool: 'read_file', args: {...}}, …])`
   runs the calls together when every one is read-only (the same
   concurrency-safe set as the agent loop), else one by one; returns
   `[{ok: true, text} | {ok: false, error}]` in order. Each counts toward
   the call limit. Faster multi-file reads in one script.

## Not now

Moving a long script to the background after 2 min; a heap limit (Boa has
none; the loop and recursion limits stay); OpenTelemetry events.

## Tests

- run_script.rs: `log`/`preview`/`sleep`, `parallel` returns ordered
  ok/error entries, limits (200 calls), a script's own `log` shadows.
- agent.rs: inner calls emit Started/Completed events; a call needing
  approval asks the handler — approved runs, denied throws; approval wait
  extends the deadline.
