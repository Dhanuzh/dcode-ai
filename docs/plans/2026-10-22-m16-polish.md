# M16 — Polish and distribution (v1.0.12)

Status: implemented

## Bug first

The Claude backend sometimes writes Claude's native function-call markup
(`<invoke name="…"><parameter name="…">…</parameter></invoke>`, plain or
namespaced, wrapped in `<function_calls>`) instead of dcode-ai's
`<tool_call>` JSON. It was printed as text, nothing ran, and the model kept
repeating the same calls for minutes. Now:

- the splitter recognizes native calls (same quoting / code-fence rules as
  `<tool_call>`), parses parameters (JSON values when they parse, strings
  otherwise) and runs them; wrapper tags vanish from the visible text;
- a call repeated word for word in one reply runs once; the third repeat ends
  the reply (loop guard);
- the protocol prompt says to use only `<tool_call>`.

## Items

1. `dcode-ai update [--check]`: latest GitHub release → download the asset for
   this platform and its `.sha256`, verify, extract with the system `tar`,
   replace the running binary (Windows: move the old exe aside first). A
   read-only location (`/usr/local/bin`) gets a clear "run with sudo" error.
2. Startup: the "is `claude` signed in" probe result is cached for 10 minutes
   in `~/.dcode-ai/cache/claude-signin.json` (only "signed in" is cached;
   logout clears it).
3. MCP: servers connect in parallel and in the background — session start
   waits at most 3 s, slower servers join at the next turn. A failed
   connection now reaches the transcript (only timeouts did before), with
   `dcode-ai mcp login <name>` for OAuth (401) failures.
4. Auto mode: a command approved by the model check gets a transcript note
   (new `AgentEvent::Notice`), e.g. "auto mode: `openssl rand -hex 4` looked
   safe to the model check — running it".
5. `--plain`: Tab opens a completion menu (slash commands, skills, `@` files).
6. `/permissions forget` clears this folder's remembered startup choice;
   `/permissions folders` lists remembered folders.
7. `/setup` picker: two columns (roles, languages) so all packs fit in the
   inline view without scrolling.
8. Sub-agents: a worktree with no changes is removed (with its branch) when the
   child finishes; one with changes is reported with the merge command.
9. The existing `install.sh` loses its stale fallback version, explains that
   Linux arm64 has no build, and mentions `dcode-ai update`. Each release
   attaches a Homebrew formula (`dcode-ai.rb`, from
   `packaging/homebrew/dcode-ai.rb.in`) ready to copy into a tap repository.
10. Release notes come from the version's CHANGELOG section.
