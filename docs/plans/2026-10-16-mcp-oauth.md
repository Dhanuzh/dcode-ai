# MCP OAuth 2.1 for remote servers (Atlassian first)

Status: ✅ implemented 2026-10-21 (steps 1–6; live-tested against Atlassian up to the browser sign-in). Date: 2026-10-16.

## Problem

`dcode-ai mcp list` shows the Atlassian plugin's server
(`atlassian_atlassian → https://mcp.atlassian.com/v2/mcp`), but no Atlassian
tools load. Verified 2026-10-16 with an unauthenticated `initialize` POST:

```
HTTP/2 401   {"error":"invalid_token"}
www-authenticate: Bearer resource_metadata="https://mcp.atlassian.com/.well-known/oauth-protected-resource/v2/mcp"
```

`HttpMcpClient` (`crates/core/src/tools/mcp.rs`) only sends static headers
from config. It has no 401 handling, no metadata discovery, no login and no
token store, so any OAuth-protected remote MCP server fails.

## What the Atlassian server supports (fetched 2026-10-16)

- Protected-resource metadata: `authorization_servers =
  ["https://auth.atlassian.com/VCeDsk8ZHncYF1g234fKtc4lNipbBhu3"]`,
  `bearer_methods_supported = ["header"]`, scopes include `offline_access`
  and `read:/write:/search:{jira,confluence}:agent-interface`.
- Authorization-server metadata (`<issuer>/.well-known/oauth-authorization-server`):
  - `authorization_endpoint` https://auth.atlassian.com/authorize
  - `token_endpoint` https://auth.atlassian.com/oauth/token
  - `registration_endpoint` `<issuer>/dcr/register` (dynamic client registration)
  - `code_challenge_methods_supported = ["S256"]`
  - `token_endpoint_auth_methods_supported = ["none"]` (public client)
  - also `pushed_authorization_request_endpoint`, `revocation_endpoint`
- Verified in step 2 (2026-10-16):
  - `grant_types_supported` includes `refresh_token`.
  - DCR accepts a loopback redirect: registering
    `http://127.0.0.1:53682/callback` with `token_endpoint_auth_method:
    none` returned 201 and a `client_id`.
  - DCR also returns a `client_secret` even for `none`. Store it as a
    secret; follow the auth method in the registration response when
    calling the token endpoint.
  - The registration response has no `registration_client_uri`, so clients
    cannot be deleted. Register once per (issuer, redirect URI) and reuse it.
  - Metadata is served at the RFC 8414 location
    `/.well-known/oauth-authorization-server/<tenant>` (and the appended
    form); OpenID locations 404.
- Still unverified: whether a different loopback port than the registered
  one is accepted. Plan: reuse the registered port; if it is busy, register
  a new client for the new port.

DCR means dcode-ai registers its own client. It never reuses another
product's OAuth client ID (project rule).

## Design

Crate responsibilities stay as they are:

| Crate | Change |
|---|---|
| `common` | `McpAuthStore`: `~/.dcode-ai/mcp-auth.json` (0600), keyed by **resource URL** (not server name, so renames and plugin vs user entries share one login). Holds client registration (`client_id`), `access_token`, `refresh_token`, `expires_at`, scopes. |
| `core` | `mcp_oauth` module: parse `WWW-Authenticate` → fetch resource metadata → fetch AS metadata → DCR → PKCE (S256) authorize URL → code exchange → refresh. `HttpMcpClient` adds `Authorization: Bearer` from the store; on 401 it refreshes once and retries; if that fails it returns a clear error (below). |
| `cli` | `dcode-ai mcp login <name>` (opens browser via existing `xdg-open` path in `oauth_login.rs`, prints the URL too for WSL/SSH, waits on a one-shot loopback listener with `state` check), `dcode-ai mcp logout <name>` (revoke + delete), `mcp list` shows `auth: signed in / needs login / static header`. |
| `runtime` | None beyond surfacing the load error in the session's MCP status. |

Rules:
- **Never start a browser login from a session or headless run.** A 401 with
  no usable token fails loudly: `MCP server "atlassian_atlassian" needs
  sign-in: run dcode-ai mcp login atlassian_atlassian`.
- A configured static `Authorization` header (API-token path) wins; OAuth is
  only attempted when no such header is set.
- Tokens are never logged; check `common/src/redact.rs` masks them (they are
  not `gho_`-style prefixed, so add the stored values to redaction at load).

## Related small fix (do first, independent)

`common::mcp_json::expand_vars` turns an unset `${VAR}` into `""`, so
`Authorization: Basic ${ATLASSIAN_MCP_AUTH}` without the env var sends
`Basic ` and yields a confusing 401. Make header expansion fail loudly
(`header Authorization references unset ${ATLASSIAN_MCP_AUTH}`) unless a
`${VAR:-default}` is given. Find call sites first; `.mcp.json` `env`
expansion may legitimately rely on empty values.
