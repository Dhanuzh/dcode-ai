# M38 — `/invite`: join with one line (v1.0.37)

Status: implemented

Joining from another computer took SSH: a server, keys, `authorized_keys`,
a firewall rule, the session id. `/invite` replaces all of that.

## For the host

`/invite` (in the TUI) starts listening on the local network (port 8788,
or `/invite <port>`) and prints one line, copied:

    dcode-ai join 192.168.1.9:8788/Qk3f9xq2… --name <your name>

When someone uses it, a prompt asks **"Priya (192.168.1.20) wants to join —
let them in?"**. Yes: they are in (office desk, messages). No, or no answer
in 60 s: refused.

- `/invite web`: the same port also serves a browser page (the `/watch` page
  plus a message box) for people without dcode-ai: `http://…:8788/?t=…`.
  Plain HTTP, so the page and the command say so.
- `/invite --let-approve`: joined people may also answer approvals and stop
  a turn. Default: only messages; approvals stay with the host.
- `/invite stop` ends it (people already in are disconnected); it ends with
  the session. A new `/invite` makes a new key.
- WSL: prints the one-time firewall commands for the port (as `/watch lan`).

## For the guest

`dcode-ai join <host:port/key> [--name]` → "waiting for the host to let you
in…" → the session live, type to send; `/quit` leaves. Same as a local join.

## Protocol

- TCP. The client sends `DCAI1` then a Noise handshake
  `Noise_NNpsk0_25519_ChaChaPoly_BLAKE2s` with PSK = SHA-256("dcode-ai
  invite v1" ‖ key). Wrong key → handshake fails → connection dropped.
  Forward secrecy from the ephemeral keys; nobody on the network can read or
  inject without the key.
- Frames: 2-byte length + Noise message; a JSON message may span frames
  (1-byte "more" flag), at most 8 MiB.
- Client → host: `hello {name}`, `say {text}`, `approve/deny {call_id}`,
  `stop`. Host → client: `admitted`, `refused {reason}`, `note {text}`,
  `event {envelope}`.
- The host side is a proxy onto the session's own IPC socket: Hello /
  Heartbeat / Say / Bye are sent for the guest (person id and name are the
  host's, not the guest's), events are forwarded. Approve/deny/stop only
  with `--let-approve`.
- The same listener serves HTTP (first bytes not `DCAI1`) when `web` is on;
  otherwise HTTP gets nothing.
- Limits: 8 guests connected or knocking at once; 10 s to finish the
  handshake; names cleaned as for `join`.

## Web chat (`/invite web`)

Page: name box + "Ask to join" → `POST /knock` (long poll for the host's
answer) → a person token → `POST /say` with it; the event stream with
`&p=<token>` keeps them present (Heartbeat) and `Bye` when it closes.

## Tests

- Unit: invite string parse; frame chunking round trip; wrong key refused.
- Host + guest end to end in-process: knock → admitted → events arrive,
  `say` reaches the session as `(from Name)`; refused path; no approvals
  without `--let-approve`.
- PTY: `/invite` prints the line, a guest joins, the host presses yes, the
  message reaches the agent; web: knock and say.
